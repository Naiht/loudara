## Functionality That Fails Or Is Unstable

- Playback is not reliable in local Vite dev.
- Public Invidious stream providers failed during the baseline run.
- The local `/s/:videoId` fallback returns `404` under Vite because the Vite middleware does not register that route.
- The Netlify `/s/:videoId` fallback depends on private `rkeys` configured in Netlify, so it is not portable to plain `pnpm dev`.
- Direct `audio.play()` can throw `NotAllowedError` when browser autoplay policy sees no qualifying user interaction.
- The player may remain in a loading state when all stream providers fail.

## Current Playback Flow

1. A user clicks a `StreamItem`.
2. `src/components/StreamItem.tsx` writes the selected track into `playerStore.stream`.
3. `StreamItem` calls `player(data.id)`.
4. `src/lib/utils/player.ts` aborts any previous request and sets player status to loading.
5. For `Topic` authors, `jioSaavn` may be attempted before YouTube stream resolution.
6. `player()` imports `src/lib/modules/getStreamData.ts`.
7. `getStreamData()` reads `sessionStorage` through `streamCache`.
8. On cache miss, it calls `getWebStreamData()` in `src/lib/platform/streamProvider.ts`.
9. `getWebStreamData()` tries public Invidious instances through `/api/v1/videos/:id`.
10. If all public providers fail, it tries the local `/s/:id` fallback.
11. When stream data is valid, `player()` stores the returned data and calls `setMetadata()`.
12. `player()` filters `adaptiveFormats` to audio streams and calls `setAudioStreams()`.
13. `setAudioStreams()` chooses a preferred stream and assigns `playerStore.audio.src`.
14. `playerStore.audio.onloadstart` calls `playerStore.audio.play()` when the internal `isPlayable` guard allows it.

## Relevant Technical Debt

- `playerStore` owns the `HTMLAudioElement`, playback events, history updates, queue progression, recommendations and theme updates.
- Components directly call playback functions and sometimes `audio.play()`/`audio.pause()`.
- Stream provider fallback logic still depends on an Invidious-shaped `Invidious` type.
- Local dev and hosted production do not expose the same stream fallback routes.
- PWA/service worker is generated only during build and has little source-level customization.
- Backend CORS and visible strings should be kept aligned with Loudara deployment domains.
- Search, list fetching, queue behavior and player state are tightly coupled through global stores.
- Build warns about ineffective dynamic imports because `getStreamData` and `setAudioStreams` are both dynamically and statically imported.
